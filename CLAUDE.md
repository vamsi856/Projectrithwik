# Rithwik website

Animated one-page site for **Rithwik Bird Feeds** and **Rithwik Industries** (Kurnool, Andhra Pradesh), a client project.
Live at https://rithwikbirdfeeds.com/ (Cloudflare Worker `projectrithwik`, deployed from the root of `main` on every
push; `wrangler.jsonc` + `.assetsignore`). The old https://vamsi856.github.io/Projectrithwik/ forwards there (inline
script in Site.astro and 404.astro); www redirects by a Cloudflare Redirect Rule. Hosting details are in README.md.

## Layout

- `site/` is the source: an Astro 5 static site (GSAP + ScrollTrigger, Lenis, three.js for the 3D packs).
- The repo root (`index.html`, `_astro/`, `img/`, `birds/` …) is **generated**: `npm run build` builds `site/dist`
  and `site/scripts/publish.mjs` copies it to the root. Never edit root files by hand.
- Three addresses, one shared page (`site/src/components/Site.astro`): `/` (the book), `/bird-feeds/` and `/human-food/`
  (Rithwik Industries). Each has its own title, description, canonical and JSON-LD; `src/pages/*` just pick the view.
  Switching is in place (`main.ts` pushes the path); old `#bird-feeds` / `#human-food` links still work.
- **Each address's HTML holds only its own view** (the small book is in all three). The other site is fetched from its
  own address on the first switch (`loadSite` in `main.ts`; it falls back to an ordinary page load). Keep it so: when
  every page held all three views, Google saw three copies of one page and listed only `/bird-feeds/` (16 Nov).
  Anything `main.ts` does to a site at start-up must also run for a site fetched later (see `loadSite`).
- SEO files are generated: `src/pages/sitemap.xml.ts`, `robots.txt.ts`, `llms.txt.ts`, `site.webmanifest.ts`.
  Titles/descriptions and the Search Console code live in `src/data/seo.ts`. The site address is `SITE_URL` in
  `astro.config.mjs` (everything follows it, the catalogue QR code too). The base is `/`: fonts are declared inline in
  Site.astro and 404.astro from the base, so nothing hard-codes a path.

## Commands (run in `site/`)

```
npm install
npm run dev                                   # http://localhost:4321/
npm run build                                 # builds and copies to the repo root
npx astro preview --port 4331                 # serve the build
node scripts/check-sizes.cjs                  # 13 widths x 3 views: no sideways spill, header OK
python3 scripts/make_photos.py                # photo sizes (pip install pillow pillow-heif)
```

Deploy = build, commit `site/` **and** the regenerated root files, push to `main`. Cloudflare redeploys in about a
minute (Workers & Pages > projectrithwik > Deployments). `publish.mjs` never touches `wrangler.jsonc`/`.assetsignore`.

## Where things are

- `site/src/data/products.ts`: every product, its variants (crop/colour options), photos, swatches, and `CONTACT`
  (phones, WhatsApp, emails, office and warehouse map links).
- `site/src/data/commons.json`: photo registry. Client photos have `own: true` and `local: 'photos/<key>.webp'`.
  Stock photos carry their Wikimedia credit, which the "Photo credits" panel lists.
- `site/src/data/photo-sizes.json`: generated by `make_photos.py`. Don't edit.
- `site/src/data/legacy.ts`: the family timeline 1925 to 2022 and `FOUNDERS` (round photo on the 2022 dot).
- `site/src/data/perches.ts`: the real birds that used to hop onto product cards (turned off).
- `site/src/scripts/main.ts`: page behaviour and animation (views, menus, paper birds, map tabs, forms, sound button).
  `flock.ts` is the hero macaw flock, `sound.ts` the birdsong and Human Food music, `pack3d.ts` the 3D packs.
- `site/src/styles/v2.css`: all styles. Components are in `site/src/components/`.

## Catalogue PDF

`site/scripts/catalogue.mjs` (`npm run catalogue`) builds `public/Rithwik-Catalogue.pdf` from products.ts, registrations,
legacy, network and the photos (converted to JPEG, ~4.5 MB). Rerun it after product/photo/contact changes, then build.
It replaced the client's Canva catalogue (which had the removed number 83097 82770 and a stray "$120.00").

## Adding a client photo

1. Crop it from the original: 4:3, **grain only, no hands or background**, at least ~800px wide if possible.
2. Save it as `site/photo-src/<key>-rithwik.webp`.
3. Add `"<key>-rithwik": {"t": "<name>", "u": "", "w": W, "h": H, "p": "", "l": "", "a": "Rithwik", "local": "photos/<key>-rithwik.webp", "own": true}` to `commons.json`.
4. Point the product (`photo: '...'`) or a single variant (`{ label: 'Red', gst: '0%', photo: '...' }`) at it in `products.ts`.
5. Run `python3 scripts/make_photos.py`, then build. To replace a photo, delete `public/img/<key>-*` first
   (the script never overwrites). When a stock photo is no longer used, remove it from `commons.json`,
   `photo-sizes.json` and `public/img`, so the credits stay accurate.

## Hosting

Static site, no server or database, on a free Cloudflare Worker (static assets only). Domain rithwikbirdfeeds.com
registered at Hostinger (until 16 Nov 2029), DNS on Cloudflare. The domain is the only running cost. DNS has no-mail
records (SPF -all, DMARC reject): change them only if the client sets up email on the domain.
